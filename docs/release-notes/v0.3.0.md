Spec0 Studio 0.3.0 is about running several requests together, and about mocks that need nothing but your computer.

## What's new

- **Collections.** A collection runs steps in order, often across several specs: create an order, get it, pay for it. Each step points at an operation in one of your specs, so its response is checked against that spec. A later step can take a value from an earlier step's response, such as the id of the order step 1 created. Right-click an operation (or a request in History) and choose **Add to collection** to start one. Collections can be saved to a folder, for example in a git repository, as YAML files that never contain secret values.
- **The Chain view** (**Steps | Chain | Runs** in a collection) shows every step in order and draws a line from each value to the field it fills. After a run, each link shows the value it passed. A link that can't work is shown in red, with the reason and a way to fix it.
- **Run logs.** **Runs** keeps a collection's last 20 runs on your computer. Each log shows every step: where it went, the values it used, the status, the schema check, and why it failed or was skipped. Copy a log as text, or export it as JSON or text.
- **Expected status.** A step can expect a code other than 2xx, such as `404` or `4XX`, to test a failure case like fetching a deleted order.
- **Local mock servers.** Press **Local mock** on any API in your library to run a mock of it on this computer, with no account and no network. It answers from the spec's examples, or builds a response from the schema, and lists anything wrong with a request in a header. It listens on `127.0.0.1` only and stops when you stop it or quit Studio.
- **Postman import.** **Import…** on the Collections tab, or drop a file there, turns a Postman collection (v2.1 or v2.0) into a Studio collection. Each request is matched to an operation in your specs where it can be. Tokens and passwords become `{{variables}}` and are never written into the collection. Status checks in test scripts become expected statuses, and values saved from a response become links between steps. A summary shows what matched and what needs your attention.
- **Request tabs.** Each operation you open gets a tab, across APIs, and the tabs come back when Studio reopens. Move between them with Ctrl+Tab and close one with ⌘W or Ctrl+W.
- **Unsent changes are kept.** What you type into a request stays there when you move to another request or restart Studio. A dot shows which requests have unsent changes, and **Discard changes** goes back to the spec's values. Going back to a request you sent earlier in the session shows its last response, marked with when it was sent.
- **A console.** **Console** in the status bar (⇧⌘Y or Ctrl+Shift+Y) lists this session's requests, collection runs, local mock requests and MCP tool calls. It is kept in memory only, and secret values show as `{{name}}`.
- **Add an API** now opens on your Spec0 organisation when you're signed in, and on a local file when you're not. Its tabs are in the order Spec0, URL, Local file.
- **Signing in** from Settings or the Mocks tab opens a "Sign in to Spec0" dialog with only the sign-in choices. Once you are signed in, it offers to browse your organisation's APIs.

## Fixes

- **Add an API** always opened on the local file tab, whatever the default was meant to be. It now opens on the right one.
- **Save as…** for a response body (an image or a PDF, for example) couldn't open the save dialog. It works now.

## Good to know

- Collections run in Studio only. There is no command-line runner yet.
- Postman scripts are never run. Only status checks and values saved from a response are converted; other scripts, OAuth 2 and digest auth, and bodies that send a whole file are noted on the step instead. Insomnia and Bruno files aren't supported yet.
- A local mock answers from examples, not state: a `POST` doesn't change what the next `GET` returns.
- Hosted mocks still need a Spec0 account. Everything else works without one.
- The Windows installer is still not code-signed. See the README for what SmartScreen shows and how to check the download.
