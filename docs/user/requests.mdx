## The request editor

Pick an operation in the **Operations** view and the editor fills itself in from the spec. Its tabs
are **Body**, **Params**, **Headers**, **Auth** and **Docs**. An operation opens on the first tab
that needs input.

- Parameters get the right kind of field: a dropdown for allowed values, a toggle for true/false. A
  required parameter starts with its example from the spec.
- Bodies start with the real field names and example values that fit each field's type and format,
  or the spec's own examples where it has them. When the spec gives nothing better, a value can be
  a placeholder such as `"string"`. **Format** indents the JSON and **Reset to example** puts the
  spec's example back.
- **Headers** lists the spec's headers, the `Content-Type` the body sets, and any you add. Put
  secrets in an environment and refer to them as `{{name}}`.
- **Docs** shows everything the spec says about the operation, including each response's schema.

Press **Send** or `⌘↵` (`Ctrl+Enter`). The arrow next to **Send** has **Copy as cURL** (`⇧⌘C`,
`Ctrl+Shift+C`), which copies the request exactly as Send builds it, and **Add to collection…**.

### Bodies and files

The editor follows the content type the spec declares:

| Content type | Editor |
|---|---|
| JSON and other text | A text body, filled in from the schema. |
| `application/x-www-form-urlencoded` | Key and value rows. Repeated keys are kept, and Studio does the encoding. |
| `multipart/form-data` | One row per part, named from the schema, each with a file picker. |

Files are read from disk when you send, so Studio has no upload size limit.

### Responses that aren't text

Images show inline. Other binary responses, such as a PDF or a zip, show their type and size, and
**Save as…** writes the bytes to a file. History records only the size of a binary body.

Servers often send JSON as `application/octet-stream`. If a binary response is really readable
text, Studio shows it as text.

## The address bar

The address bar holds the method, where the request goes, and the operation's path. Where it goes
is chosen here, separately from your environment. See
[Targets and environments](/targets-and-environments).

- The target shows a server's host, an environment's name, **Local mock** (with its port) or
  **Hosted mock**. Its tooltip has the full address.
- The target menu lists the spec's servers, the environments Spec0 knows the API is deployed to,
  its [hosted mock](/hosted-mocks), its [local mock](/local-mocks) when one is running, and
  **Custom URL…**.
- **Custom URL…** takes any base URL, such as `http://localhost:8080`. A spec with no `servers`
  works too.
- The path belongs to the operation, so you can't edit it. Its `{parameters}` are highlighted.

A new API starts on the spec's first server. The response pane and History say where each request
went, so you know whether you called a real server.

If the spec's server is a path, such as `/api/v3`, Studio resolves it against the address of a
spec added from a URL. A spec from a local file has nothing to resolve against, so type the base
URL yourself. The bookmark icon saves a typed address as `baseUrl` in the active
[environment](/auth-environments#environments).

<Callout title="No CORS">
The app sends requests itself, so browser CORS rules don't apply. There's no preflight and no proxy
to set up.
</Callout>

## Request tabs

Every operation you open gets a tab above the API bar. Tabs work across APIs, so a request from the
Orders API can sit next to one from the Payments API. **+** opens a [scratch](#the-scratch-pad)
request.

Close a tab with its **×**, a middle-click or `⌘W` (`Ctrl+W`). `Ctrl+Tab` and `Ctrl+Shift+Tab` move
between tabs (also `⇧⌘]` and `⇧⌘[` on macOS). With no tab on screen, `⌘W` closes the window.

Tabs come back when Studio reopens. Studio keeps up to 20. Opening another closes the one you used
longest ago, but never one with unsent changes.

## Unsent changes

What you type into a request stays with it when you switch away, and after a restart. A dot on the
tab and next to the operation marks unsent changes. **Discard changes** goes back to the values the
spec suggests. Once you send, the request opens with what you sent.

Auth values typed straight into a request are kept only until Studio quits. A `{{reference}}` to an
environment variable is kept. Secret values are never written into saved changes.

## The last response comes back

Going back to a request you sent earlier in the session shows its last response. If you've edited
the request since, a note says that response doesn't match what's on screen.

## The scratch pad

**Scratch**, pinned first in your library, sends one request to a URL you type. Environment
variables work there. There's one pad and nothing to save. With no spec there's nothing to check
the response against, and the response pane says so. Scratch requests go to History.

## History

History is a read-only log of every request you've sent. It stays on your computer for 30 days and
is never synced.

**History** in the top bar lists every request by day, scratch ones included. Chips filter by API,
by status, by mock or real server, or to **Drift only**. For one API, choose **History** in its
sidebar.

An entry shows what was sent and received, the environment, where it went, and the
[schema check](/checking-responses) from that time. If the spec has changed since, **Re-check
against current spec** runs the check again. The spec decides what counts as correct.
See [The spec is the source of truth](/source-of-truth).

An entry can't be re-sent, so it always shows what happened. **Open as new request** fills the
editor from it. **Add to collection** adds it as a [collection](/collections) step with the values
it was sent with.

To delete everything, use **Clear all history…** in the list's **⋯** menu, or **Clear history** in
**Settings → Data & privacy**. Secret values are never written into History.
