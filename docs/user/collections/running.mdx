This page covers running a collection, what makes a step pass, and the run log that records each
run.

## Run it

Press **Run** in the collection header. Studio sends the steps one at a time, in order, using the
active environment.

- **Stop at first failure** is on by default: the first failing step ends the run, and the steps
  after it are marked as not run. Untick it to run every step whatever happens.
- A step **passes** when its status is the one it expects, **and** its response matches what its
  spec declares for that status.
- The whole run is one entry in [History](/requests#history), with its steps inside it.

While it runs, the status bar at the bottom shows the collection and the step, such as "Running
Checkout · step 2 of 5", with a progress bar, on whatever page you're on. Click it to open the run.

When the run ends, a notice says whether it passed, or which step failed and why, with **View run**.
A passed notice goes away after a few seconds; a failed one stays until you close it. If you started
the run from the collection's page, Studio opens its log for you. Runs an agent started, or runs
that finish while you're on another page, only show the notice, so you aren't moved away from what
you're doing.

The header then shows the last run's result, such as "Last run: 2 passed · 1 failed · 9 ms".

## Expected status

A step expects any 2xx unless you say otherwise. To test a failure case, such as getting a deleted
order or paying twice, set the step's **Expects** field:

| Expects | Passes when the status is |
|---|---|
| (empty) | any 2xx |
| `404` | exactly 404 |
| `4XX` | any 4xx |

The step also checks the response against what the spec declares for that status, such as an error
schema for `404`. If the spec declares nothing for it, the step passes on the status alone and says
the body wasn't checked. A step with a non-default expectation shows it in the list ("expects 404").

With nothing set, a `3xx` fails. Studio follows redirects, so a 3xx rarely reaches a step.
</Callout>

## The run log

Choose **Runs** in the collection header. It lists the collection's last 20 runs; select one to see
its log.

For each step, the log shows:

- when it started, its method, URL and target
- the status, time and size of the response, and warnings from a local mock
- the expected status, and the schema check
- the values it took from earlier steps, and the value each one had, or why it couldn't be found
- whether it passed

A failed step says why: a network error, an unexpected status, a schema difference, or a value
that couldn't be found. A step that didn't run says why it was skipped.

**Copy as text** copies the log. **Export JSON…** and **Export text…** save it to a file.
**Clear** removes the collection's runs.

<Callout title="Good to know">
- Run logs are kept on your computer, next to Studio's other data: the last 20 runs per
  collection. They're never sent anywhere.
- Secret values are replaced by their `{{name}}` in the log and in exports, including secrets you
  add to an environment after the run.
- Every run also appears in the [console](/console), with a link to its log.
- A run a coding agent started says which agent, in the Runs list and in its log. See
  [Local MCP server](/mcp).
</Callout>
