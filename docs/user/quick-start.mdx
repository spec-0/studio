**Spec0 Studio** is a free, open source desktop app for calling and testing APIs, built around
your OpenAPI spec. You open a spec, Studio builds the requests from it, and every response is
checked against the spec as it arrives. It runs on macOS, Windows and Linux, it needs no account,
and it sends no telemetry.

This page gets you from download to a checked request, a mock, a small test flow and a coding
agent that can use your APIs. Each step links to the full page if you want more.

## 1. Download

<Tabs items={['macOS', 'Windows', 'Linux']}>
  <Tab value="macOS">

[spec0-studio-macos-universal.dmg](https://github.com/spec-0/studio/releases/latest/download/spec0-studio-macos-universal.dmg).
Open it and drag Studio to Applications. macOS 11 or later, Apple silicon and Intel. The app is
signed and notarized, so it opens without a warning.

  </Tab>
  <Tab value="Windows">

[spec0-studio-windows-x64-setup.exe](https://github.com/spec-0/studio/releases/latest/download/spec0-studio-windows-x64-setup.exe).
Windows 10 and 11 (x64), no admin rights needed. The installer isn't code-signed yet, so
SmartScreen will likely warn you: click **More info**, then **Run anyway**.

  </Tab>
  <Tab value="Linux">

[AppImage](https://github.com/spec-0/studio/releases/latest/download/spec0-studio-linux-x86_64.AppImage)
for most distributions, or
[.deb](https://github.com/spec-0/studio/releases/latest/download/spec0-studio-linux-amd64.deb) for
Debian and Ubuntu. Needs WebKitGTK 4.1 (Ubuntu 22.04, Debian 12 or newer), x86_64 only.

  </Tab>
</Tabs>

## 2. Add an API

Press `⌘O` (`Ctrl+O` on Windows and Linux). Choose **Local file** for a spec on your computer
(or drop it on the window), or **URL** and paste an address. To try it with a public spec:

```text
https://petstore3.swagger.io/api/v3/openapi.json
```

No spec at hand? On an empty library, **Try the sample API** opens a small Orders API that comes
with Studio. Studio reads OpenAPI 3.0 and 3.1 and Swagger 2.0, in YAML or JSON.
More in [Specs and the library](/library).

## 3. Send a request and read the check

Pick an operation in the list on the left. The form is built from the spec: path and query
parameters, headers, auth, and a body filled in from the spec's examples. Press `⌘↵`
(`Ctrl+Enter`) to send.

The response appears on the right. At its top, Studio says whether it **matches** the schema the
spec declares for that status, and if not, which fields are wrong, missing or not in the spec at
all. The request editor's **Docs** tab shows everything the spec says about the operation.
More in [Sending requests](/requests) and [Checking responses](/checking-responses).

## 4. Start a mock

No server yet, or don't want to call the real one? Press **Local mock** in the API's bar. Studio
starts a mock of that spec on `127.0.0.1`, answering from the spec's examples, and the address bar
can send to it straight away. Nothing leaves your computer.

## 5. Chain requests into a collection

Right-click an operation and choose **Add to collection ▸** and a new or existing collection. Add
a second one, then press the link button next to one of its parameters to pass in a value from
the first step's response, such as a new order's `id` into `GET /orders/{orderId}`. Press **Run**: the steps go in order, and each one is checked against its
own spec. Steps can come from different APIs.
More in [Collections](/collections) and [Passing values between steps](/collections/chaining).

## 6. Let your coding agent use it

Open the **MCP** tab, press **Start**, and copy the one-line setup for Claude Code, Cursor or
another client. Your agent can then read your specs, send requests, start local mocks and run
collections through Studio. Studio asks you before an agent's first request to each host.
More in [Local MCP server](/mcp). To chat with an agent inside Studio instead, see
[Agent chat](/agent-chat).
