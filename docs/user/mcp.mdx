Studio can run an [MCP](https://modelcontextprotocol.io) server on your computer. A coding agent,
such as Claude Code or Cursor, can then read the specs in your library (published or not), add
specs to it, send requests, start local mocks, build and run collections, and check a running
server against its spec.

Requests go through Studio, so they use your environments, proxy and certificate settings, and
responses are checked against the spec. You decide which hosts an agent may call.

The server is **off by default**. Starting a chat in the [agent chat](/agent-chat) starts it and
connects the agent for you.

## Turning it on

Open the **MCP** tab in the top bar and choose **Start**. The panel then shows:

- **Address**: `http://127.0.0.1:47321/mcp`. If port 47321 is taken, Studio uses the next free
  port and tells you. You can also choose a port.
- **Token**: a secret the agent sends with every request. It stays hidden until you show it.
- **Connect an agent**: setup text for Claude Code, Cursor and other clients.

## Connecting an agent

Copy the setup text from the panel. The examples below show `<your token>` in place of your token,
and the default port.

  <Tab value="Claude Code">

Run this in a terminal:

```bash
claude mcp add --transport http spec0-studio http://127.0.0.1:47321/mcp --header "Authorization: Bearer <your token>"
```

  </Tab>
  <Tab value="Cursor">

Add this to `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "spec0-studio": {
      "url": "http://127.0.0.1:47321/mcp",
      "headers": {
        "Authorization": "Bearer <your token>"
      }
    }
  }
}
```

  </Tab>
  <Tab value="Other clients">

Most MCP clients accept a JSON file in this shape:

```json
{
  "mcpServers": {
    "spec0-studio": {
      "type": "http",
      "url": "http://127.0.0.1:47321/mcp",
      "headers": {
        "Authorization": "Bearer <your token>"
      }
    }
  }
}
```

  </Tab>

The copied text contains your token. Don't commit it or paste it anywhere public.

## What agents can use

Tools marked **asks** wait for your approval (see [Approving what agents do](#approving-what-agents-do)).
Tools marked **sign-in** need Studio to be signed in to Spec0.

### Reading your APIs

| Tool | What it does |
|---|---|
| `list_local_apis` | Lists the APIs in your library: title, version, source, operation count, base URLs, and whether each has a hosted mock. |
| `get_api_spec` | Returns an API's OpenAPI document as stored. Large documents come back in parts. |
| `get_operation` | Returns one operation: parameters, request body schema, responses, security schemes, and the full URL for each server. |
| `search_operations` | Searches operations by path, operationId, summary, tag and description. With an API and no search text, lists its operations. |
| `list_environments` | Lists your environments, the active one, and each variable's name. Values only for variables that aren't secret. |
| `get_connection_status` | Says whether Studio is signed in to Spec0. |

### Sending requests and checking a server

| Tool | What it does | |
|---|---|---|
| `send_request` | Sends one request (for an operation, or to any URL) and returns the status, headers, body and schema check. Studio fills in `{{variables}}`, secret ones too, hides credential headers in the result, and adds the request to History. | asks |
| `check_contract` | Calls each operation on a base URL, such as `http://localhost:8080`, and reports the status and schema check for each. Only `GET`, `HEAD` and `OPTIONS` run unless the agent asks for the others. | asks |

### Local mocks

| Tool | What it does | |
|---|---|---|
| `list_local_mocks` | Lists running local mocks and their addresses. | |
| `start_local_mock` | Starts a [local mock](/local-mocks) and returns its address. | asks |
| `stop_local_mock` | Stops an API's local mock. | |

### Collections

| Tool | What it does | |
|---|---|---|
| `list_collections` | Lists collections, which are agent drafts, each one's file, and its last run. | |
| `get_collection` | Returns a collection's steps in order, with targets, parameters, bodies, expected statuses and links. | |
| `create_collection` | Creates a draft, empty or as a copy of another collection. | |
| `add_step`, `update_step`, `remove_step` | Change a draft's steps. | |
| `link_value` | Fills a step's field from an earlier step's response, such as a new order's id. See [Chaining](/collections/chaining). | |
| `set_expected_status` | Sets the status a step expects, such as `404` or `4XX`. | |
| `run_collection` | Runs a collection and returns each step's status, whether it passed, and why not. | asks |
| `get_run_log` | Returns a run's log: each step's request, response, schema check and passed values. | |
| `save_collection_to_folder` | Saves a collection as a `.spec0-collection.yaml` file, for example in your repository. | asks |

### Specs

| Tool | What it does | |
|---|---|---|
| `open_spec` | Adds a spec to your library from a file path or an `http(s)` URL, the same as **Open**, and returns its id, title, version and number of operations. Swagger 2.0 is converted as it is when you open it. A spec that's already in the library isn't added twice; the agent is told to use `reload_spec`. | asks |
| `reload_spec` | Reads a spec again from its file or URL and reports what changed: version, servers, and operations and schemas added, removed or changed. | |
| `validate_spec` | Reports problems that stop a spec loading or make operations hard to use, such as a broken reference or an undeclared path parameter. | |

### Hosted mocks

| Tool | What it does | |
|---|---|---|
| `get_mock_server` | Returns an API's hosted mock address, its key (if Studio has it), the key header, and a curl command. | sign-in |
| `create_mock_server` | Creates a hosted mock for an API already published to Spec0, or returns the existing one. | sign-in |
| `refresh_mock_server` | Rebuilds the hosted mock from the latest version on Spec0. Address and key stay the same. | sign-in |

For OAuth 2.0, Studio uses the token it holds for that API and environment, so get one in the
API's [Auth section](/auth-environments#oauth-20) first. A hosted mock needs the API
[published to Spec0](/document#publishing-a-local-spec-to-spec0). See [Hosted mock servers](/hosted-mocks).

## Approving what agents do

Studio asks you in a dialog before an agent:

- sends its first request to a host, including hosts on your computer, for example "Claude Code
  wants to send requests to localhost:8080".
- sends a `DELETE`, `PUT` or `PATCH` to a host that isn't on your computer. Studio asks this even
  when you've already allowed the host.
- starts a local mock.
- saves a collection to a file. Studio asks every time and shows the path.
- adds a spec to your library. Studio asks every time and shows the path or URL. A URL is fetched
  with one `GET` request, so blocked hosts are refused and the fetch counts towards the request
  limit. Allowing it doesn't allow the agent to send other requests to that host.

Answers are **Don't allow**, **Allow once** and **Allow for this session** (until you stop agents
or quit Studio). Saving a file and adding a spec can only be allowed once.

**Don't allow** is selected by default, and `Esc` does the same, so a stray key press lets nothing
through. An unanswered approval is refused after five minutes.

Every waiting approval is also in the [bell](/notifications) in the top bar, where you can answer
it too. While one waits, Studio's Dock icon bounces (its taskbar button flashes on Windows) and the
window title says a request is waiting, so you see it even with Studio behind other windows. One
that's refused because nobody answered, or because you stopped agents, stays in the bell under
**Missed**, with when and why.

### Blocked hosts and the request limit

Under **Agents** in the MCP tab:

- **Blocked hosts**: hosts agents can never send to, one per line, such as production.
- **Requests a minute**: a cap on requests from all agents together (60 by default). Over it,
  Studio refuses the request and tells the agent to wait.

### Secret values

Agents never see secret values. An agent writes `{{token}}`, and Studio fills in the value when it
sends the request. Tool results and the activity log show `{{name}}` in place of each secret value.

## Collections agents build

A collection an agent creates is a **draft**, shown in **Collections** with a banner naming the
agent. **Keep** (or saving it to a file) makes it an ordinary collection. **Discard** deletes it, after you confirm.

Agents can change only their own drafts. Your collections they can read, run or copy, but not
change. The **Runs** view and run log name the agent that started a run.

## Seeing what agents did

The **Agents** section of the MCP tab shows the agents connected since Studio started, the hosts
you allowed, and an **Activity** log of each tool call and request, with what was sent and what
came back. It covers this session only. The [console](/console) also records each tool call and
which agent made it.

**Stop agents** refuses everything agents are waiting for, stops their runs, forgets what you
allowed this session, and stops the server. Every approval dialog has the same button.

## Security

Only programs on your computer that have the token can reach the server. It listens on
`127.0.0.1`, refuses requests without the token, and refuses web pages, so a site you visit can't
reach it. It runs only while Studio is open. Agents never see secret values, and the first request
to each host waits for you. **Regenerate** makes a new token. Agents using the old one stop working
until you give them the new setup text.

## Local and remote MCP servers

Studio's server knows what is in Studio on your computer, including unpublished specs, and sends
requests. It needs no Spec0 account, except for the hosted mock tools.

The [Spec0 MCP server](https://docs.spec0.io/docs/agents#spec0-mcp-server) is hosted by Spec0. It
searches your organisation's APIs, public APIs on the Spec0 registry (by `orgSlug/apiSlug`) and the
Spec0 docs. It sends no requests, and needs an account for your organisation's APIs. You can use
both at once.
