A **hosted mock** runs on Spec0, so anyone in your organisation with its address and key can call
it, including CI. It needs a Spec0 account. For a mock just for you, a
[local mock](/local-mocks) needs none.

## Create a hosted mock

Open the **Create a mock server** dialog from:

- **Create mock** in the bar of an open API
- **Create hosted mock…** in the **⋯** menu on the API's card in the library
- **Create hosted mock** in the **Mocks** tab, which then asks which API
- the end of an API's row in **Add API → Spec0**

If the API already has a hosted mock, the API bar and the card's menu show **Hosted mock** instead.

Steps already done are ticked and skipped.

<Steps>
<Step>

**Sign in to Spec0.** Choose **Use your spec0 CLI sign-in** (if you've signed in with the
[CLI](https://docs.spec0.io/docs/cli)) or **Sign in with a browser**. See [Signing in](/connect#signing-in).

</Step>
<Step>

**Choose a team.** Pick the team that owns this API (you can move it later). Skipped if the API is
already on Spec0, or you belong to one team or none.

</Step>
<Step>

**Publish to your organisation.** A hosted mock serves a published spec version (see
[The spec is the source of truth](/source-of-truth)), so an API added from a file or URL is
published first, visible only inside your organisation. Choose the **API name** (lower-case letters,
digits and dashes) and the **Version** (from `info.version`). The dialog warns about breaking
changes against a version already published under that number. Skipped if the API is already on
Spec0.

</Step>
<Step>

**Create the mock.** Spec0 builds it from the published spec and gives it an address and a key.

</Step>
</Steps>

**Send a test request** sends one of the API's operations to the new mock.

From then on, Studio sends that API's requests to the mock, and the address bar, response and
History say **Hosted mock**. To go back to a real server, pick it in the address bar.

## The address and the key

Each hosted mock has its own address and key. Send the key in an `X-Mock-API-Key` header.

Studio gets the key from Spec0, keeps it on your computer, and adds the header. If it can't (for
example, you're signed out), it asks you to paste it from the mock's page in Spec0.

Spec0 can't show some older keys. For those, Studio offers **Make a new key**. The old key stops
working at once, so update anything else using it.

<Callout type="warn">
Treat the key like a password. Anyone with the address and the key can call the mock. If a key has
been shared too widely, [regenerate it](#regenerate-the-key).
</Callout>

## Call it from anywhere

A hosted mock is an ordinary HTTPS address:

```bash
MOCK_URL="<the mock's address, copied from Studio>"
MOCK_KEY="<the mock's key, copied from Studio>"

curl -s "$MOCK_URL/orders" -H "X-Mock-API-Key: $MOCK_KEY"
```

Replace `/orders` with a path from your spec.

## What it answers with

For each response, a hosted mock uses the first of:

1. examples on the response's media type (`example` or `examples`)
2. examples on the schema, then on each property
3. defaults and enum values, for fields with no example
4. generated values based on the field's type and format

## Rebuild

A hosted mock keeps serving the spec version it was built from. **Rebuild mock** makes it serve the
version on Spec0 now. The address and key stay the same, so callers don't change.

When the mock is behind the spec you have open, the library card shows **Mock is behind** with both
versions, and the response pane says so, so you don't mistake it for drift. If you changed the spec
locally, publish it first, then rebuild.

## Regenerate the key

**Regenerate key** gives the mock a new key and keeps the address. Studio asks first, because the
old key stops working at once, for everyone.

## Limits

Your organisation's plan sets how many mock servers and APIs you can have. The dialog shows your
usage when Spec0 reports it, and warns before you start if you're at a limit. If you reach one
part-way, it says so, for example "You've used 3 of 3 mock servers on the Free plan". **Settings →
Account & Spec0** shows your plan.

## If something goes wrong

If your sign-in expired, the dialog returns to sign-in, then carries on. If Spec0 can't be reached,
you can try again. Cancelling a browser sign-in changes nothing.

## From the MCP server

With the [local MCP server](/mcp), a coding agent can get, create or rebuild a hosted mock while
Studio is signed in to Spec0.
